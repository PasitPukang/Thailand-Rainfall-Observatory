# รายงานตรวจสอบข้อมูลและผลคำนวณ

ตรวจเมื่อ **4 ตุลาคม 2026** จาก PostgreSQL และไฟล์ที่เผยแพร่ในโครงการ ข้อมูลหลักสิ้นสุดวันที่ **26 กันยายน 2026** ส่วนไฟล์ดิบและไฟล์ที่ทำความสะอาดของวันที่ 27 กันยายนยังไม่ได้โหลดเข้าฐานข้อมูล

## สรุปผล

| เรื่องที่ตรวจ | ผล |
| --- | --- |
| ข้อมูลรายชั่วโมง | 5,896,968 แถว · 77 จังหวัด · 1 ม.ค. 2018–26 ก.ย. 2026 |
| ข้อมูลรายวัน | 245,707 วันจังหวัด · ทุกวันจังหวัดมี 24 ชั่วโมง |
| ค่าว่างและค่าหลุดช่วงที่ ETL กำหนด | 0 แถวจากข้อมูลรายชั่วโมงทั้งชุด |
| JSON ดิบเทียบ CSV รายชั่วโมง | ตรวจ 5,896,968 แถวจากไฟล์ดิบหลัก 770 ไฟล์ · เวลาและตัวแปรทั้ง 4 ตรงกันทุกแถว |
| PostgreSQL รายชั่วโมงเทียบรายวัน | ผลรวมฝน ค่าเฉลี่ย/สูงสุดอุณหภูมิ ค่าเฉลี่ยความชื้น และลมสูงสุดตรงกันทั้ง 245,707 วันจังหวัด ภายในค่าคลาดเคลื่อน 0.000001 |
| CSV สำหรับ Power BI เทียบ CSV รายชั่วโมง | 245,707 วันจังหวัดตรงกันทุกค่าที่ตรวจ หลังส่งออก CSV ปี 2026 ใหม่ |
| การจัดชั้นฝนจากผลรวมรายวัน | ตรงกับสูตรในระบบทุกแถว |

ความครบถ้วนตามโครงสร้างคิดจาก **77 จุด × 3,191 วัน × 24 ชั่วโมง = 5,896,968 แถว** ไม่มีวันที่มีชั่วโมงขาดหรือซ้ำ คีย์ `(province_id, weather_time)` ใน PostgreSQL เป็น primary key และไฟล์ CSV รายชั่วโมงเรียงตามคีย์โดยไม่พบคีย์ซ้ำ

ขนาดไฟล์หลักบนดิสก์: JSON ดิบ 927 ไฟล์ **34.0 MiB**, CSV รายชั่วโมงแยก 9 ปี **371.6 MiB**, CSV สำหรับ Power BI **16.4 MiB**, SQLite ชุดทดลองเก่าถึงปี 2025 **561.4 MiB**, และรายงาน PBIX **1.9 MiB** ขนาด ZIP ของทั้งโปรเจกต์จะแตกต่างจากผลรวมนี้เพราะมีการบีบอัด

ไฟล์ `data/raw/` มี 927 ไฟล์ รวมไฟล์ที่ช่วงเวลาทับซ้อนกันและไฟล์วันที่ 27 ก.ย.; เปิดอ่านและตรวจจำนวนแถว/เขตเวลาครบทุกไฟล์ `data/cleaned/` มี 154 ไฟล์ รวม 3,696 แถว; เวลาและค่าอากาศทุกแถวตรงกับ JSON ดิบของวันที่เกี่ยวข้อง

ก่อนตรวจพบว่า `database/export/fact_weather_hourly_2026.csv` หยุดที่ 25 ก.ย. และขาดข้อมูล **1,848 แถว** เมื่อเทียบกับ PostgreSQL จึงส่งออกปี 2026 ใหม่ ขณะนี้ CSV รายชั่วโมงมีจำนวนเท่ากับ PostgreSQL และไม่มีวันรายวันที่ตกหล่น

ทดสอบการติดตั้งบนฐาน PostgreSQL ว่างที่แยกจากฐานจริงโดยนำเข้า CSV ทั้งชุดผ่าน `seed-postgres` ได้ **5,896,968 แถวรายชั่วโมง, 245,707 แถวรายวัน, 77 จังหวัด** แล้วลบฐานทดสอบหลังตรวจเสร็จ

## ผลทดสอบการประเมินฝนบนเว็บ

เว็บใช้ความถี่วันที่ฝน ≥0.1 มม. ในช่วง ±15 วันของวันเดียวกันตามปฏิทินจากปี 2018–2025 แล้วคำนวณ `(วันที่ฝนตก + 1) / (ตัวอย่างทั้งหมด + 2)` ค่าที่ได้เป็นโอกาสตามฤดูกาล ระบบตอบว่า “มีแนวโน้มฝนตก” เมื่อค่า ≥50%

| ชุดทดสอบ | จำนวนวันจังหวัด | ความแม่นใช่/ไม่ใช่ | ทายว่าฝนตกทุกวัน | Brier score (ยิ่งต่ำยิ่งดี) |
| --- | ---: | ---: | ---: | ---: |
| ปี 2018–2025 แบบเว้นปีที่ทดสอบออกจากการคำนวณ | 224,994 | 81.78% | 66.12% | 0.1293 |
| ปี 2026 ถึง 26 ก.ย. ซึ่งไม่อยู่ในชุดปีที่ใช้คำนวณ | 20,713 | **83.74%** | 70.15% | **0.1087** |

ปี 2026 มี precision **86.56%** และ recall **90.94%** สำหรับคำตอบ “ฝนตก”; ทายถูก 17,345 จาก 20,713 วันจังหวัด ค่า Brier ของอัตราฝนตกเฉลี่ยรายจังหวัดที่ไม่ดูฤดูกาลเท่ากับ **0.2070** การทดสอบนี้ใช้ ERA5 เป็นทั้งข้อมูลย้อนหลังและคำตอบจริง จึงวัดความสอดคล้องภายในข้อมูลแบบจำลอง **ยังไม่พิสูจน์ความแม่นต่อสถานีตรวจวัดฝนจริงหรือพยากรณ์อากาศสด**

เว็บประมาณฝนรายเดือนจากมัธยฐานของเดือนเดียวกันในปี 2018–2025 เมื่อทดสอบแบบเว้นปีออก ค่าเฉลี่ยของความคลาดเคลื่อนสัมบูรณ์ (MAE) คือ **46.6 มม./เดือน/จุด** จาก 7,392 เดือนจังหวัด เมื่อใช้ปี 2026 เดือน ม.ค.–ส.ค. เป็นข้อมูลนอกชุดประวัติ ค่า MAE คือ **30.3 มม.**, ค่ามัธยฐานของความคลาดเคลื่อน **18.3 มม.**, และผลรวมความคลาดเคลื่อนสัมบูรณ์คิดเป็น **27.0%** ของผลรวมฝนจริงในชุดทดสอบ 616 เดือนจังหวัด จึงควรใช้เป็นค่าฐานตามฤดูกาล ไม่ใช่พยากรณ์เดือนข้างหน้าแบบเรียลไทม์

## ข้อจำกัดที่มีผลต่อความหมายของผลลัพธ์

1. **ความถูกต้องต่อโลกจริงยังไม่ทราบ**: [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) ระบุว่า ERA5 เป็น reanalysis ความละเอียดประมาณ 0.25° หรือ 25 กม. โครงการใช้หนึ่งจุดตัวแทนต่อจังหวัด ไม่ใช่ค่าเฉลี่ยพื้นที่จังหวัด ไม่มีการเทียบกับเครื่องวัดฝนหรือสถานีอุตุนิยมวิทยาไทย ในข้อมูลตอบกลับปี 2018 จุดของกรุงเทพมหานครและนนทบุรีมีพิกัดกริดเดียวกัน จึงไม่ใช่ตัวอย่างอิสระ 77 จุดเต็มที่
2. **นิยามวันฝน**: Open-Meteo ระบุว่า `precipitation` ณ ชั่วโมงที่แสดงเป็นผลรวมของ *ชั่วโมงก่อนหน้า* แต่ระบบปัจจุบันรวมแถวที่ติดป้ายเวลา 00:00–23:00 ของวันเดียวกัน เมื่อลองเลื่อนเวลาหนึ่งชั่วโมงเพื่อจัดเป็นวันปฏิทินจริง ผลรวมรายวันเปลี่ยนใน 67,759 จาก 245,630 วันจังหวัดที่เทียบได้ และชั้นฝนเปลี่ยน **217 วันจังหวัด** (0.088%); ความต่างเฉลี่ยสัมบูรณ์ **0.180 มม.** ควรปรับนิยาม/ป้ายกำกับวันก่อนใช้ค่ารายวันเทียบแหล่งอื่นโดยตรง
3. **เกณฑ์ฝนหนักกับรอบวัด 07:00 น.**: ระบบใช้ตัวเลขเกณฑ์ 35.1 และ 90.1 มม. ของ [กรมอุตุนิยมวิทยา](https://www5.tmd.go.th/info/%E0%B9%80%E0%B8%81%E0%B8%93%E0%B8%91%E0%B8%AD%E0%B8%B2%E0%B8%81%E0%B8%B2%E0%B8%A8) แต่ใช้ 24 ชั่วโมงตามป้ายเวลาปฏิทิน ขณะที่เกณฑ์ข้อมูลวัดฝนรายวันของกรมใช้รอบเริ่ม 07:00 น. หากจัดกลุ่มข้อมูล ERA5 เป็นรอบ 07:00 น. แทน ชั้นฝนเปลี่ยน **3,187 จาก 245,630 วันจังหวัด** (1.30%) ตัวเลขฝนหนักในโครงการจึงไม่ควรกล่าวว่าเท่ากับจำนวนวันฝนหนักของกรมฯ
4. **Power BI เมื่อเลือกทุกจังหวัด**: รายงานฉบับปรับปรุงใช้ measure `Rainfall per point (mm)` และ `Heavy Days per point` สำหรับการ์ดและกราฟแนวโน้ม เพื่อแสดงค่าเฉลี่ยต่อจุดตัวแทน เช่นฝนปี 2025 เท่ากับ **1,679.3 มม./จุด** ไม่ใช่ผลบวก **129,305.8 มม.** จาก 77 จุด หากใช้ measure `Total Rainfall (mm)` เดิมในงานต่อยอด ต้องระบุว่าคือผลบวกข้ามจุด ไม่ใช่ค่าฝนทั้งประเทศ
5. **ปี 2026 ยังไม่เต็มปี**: การเปรียบเทียบยอดฝนทั้งปี 2026 กับปี 2018–2025 โดยไม่ระบุช่วงเวลาจะทำให้เข้าใจผิด และรายงาน PBIX เป็น snapshot ต้องกด Refresh หลัง Airflow ส่งออก CSV ใหม่

## ทำซ้ำการตรวจ

```powershell
python audit/compare_raw.py
python audit/verify_exports.py
python -m unittest discover -s tests -q
```

ผลรอบนี้อยู่ใน [`raw_comparison.json`](raw_comparison.json) และ [`metrics.json`](metrics.json) การตรวจ PostgreSQL ใช้ SQL รวมกลุ่มจาก `fact_weather_hourly` แล้วเทียบทุกคอลัมน์กับ `mart_weather_daily` โดยยอมให้เลขทศนิยมต่างกันไม่เกิน 0.000001 การตรวจความแม่นใช้การเว้นปีและข้อมูลปี 2026 ตามที่อธิบายข้างต้น

**ข้อสรุป:** ความครบถ้วนและความสอดคล้องภายในแหล่งข้อมูล/การแปลงข้อมูลที่ตรวจอยู่ในระดับสูงมากหลังแก้ CSV ปี 2026 แต่ยังไม่สามารถระบุ “เปอร์เซ็นต์ความถูกต้องของฝนจริงในประเทศไทย” ได้จนกว่าจะมีข้อมูลสถานีภายนอกสำหรับตรวจเทียบ

ผลตรวจว่าฟังก์ชันและรายงานตรงกับหัวข้อโครงการอยู่ใน [รายงานตรวจความตรงตามหัวข้อ](TOPIC_COVERAGE_TH.md)
